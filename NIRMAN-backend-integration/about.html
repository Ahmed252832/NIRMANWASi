About the system

A record is useful when responsibility stays attached to it.

NIRMAN is an academic DBMS application for real-estate and construction operations. Its interface follows the relationships defined in its Oracle data model.

System structure04Purpose-specific roles
Data before decoration

Every screen starts from a supported relationship.

NIRMAN does not infer project ownership, financial profit, or operational authority when the schema does not support it. Public data is limited, while authenticated workspaces are constrained by role and ownership.

Role boundaries

Useful access without a universal data view.

ADM / oversight

Admin

System-wide management and review, backed by a real Employee identity for operational records.

EMP / operations

Employee

Owned tenders, assigned payment and complaint queues, pending allocations, issued awards, and supervised delivery.

CLI / ownership

Client

Personal profile, bookings, payments, installments, complaints, and public property discovery.

REP / delivery

Contractor Representative

Represented-contractor context, open tenders, own bids, awarded projects, and authorized progress updates.

Availability

Status plus booking absence

Available means the unit is marked Available and does not occur in Booking.

Progress

Latest dated update

Current progress follows update date and update ID, not the maximum percentage ever recorded.

Security

Policy on the server

Sessions, roles, ownership, CSRF, and actor identity are checked by PHP before Oracle work occurs.
